## 1    项目提出

### 项目名称
新一代AI Agent企业全流程数字化管理平台（MeridianERP）

### 项目简介
MeridianERP 是一个面向**工厂总部 · 分店 · B2B 渠道经销商**的多租户 SaaS ERP 系统，集成 AI Agent 智能诊断能力，覆盖企业全流程数字化管理，包括 CRM 客户关系管理、进销存管理、配额/补货协同、佣金结算、消费者店面（自提或配送）、平台资金总览及 AI 运营诊断。

平台采用"一后端多门户"架构：NestJS 统一 API 服务四个 Next.js 前端门户（工厂总部管理后台、分店商户后台、渠道经销商门户、消费者商店前端），通过 JWT 多域认证实现角色隔离，基于 Prisma ORM + PostgreSQL 实现多租户数据隔离，Redis + BullMQ 驱动异步任务（邮件、佣金结算），Stripe 处理支付。

AI Agent 模块嵌入 Admin 后台，运营人员通过自然语言查询业务异常（订单佣金、资金台账、库存水位、履约状态），LLM Agent 自动调用诊断工具链追踪代码路径，综合多域数据输出结构化诊断报告。

### 项目目标

| 序号 | 目标 | 说明 |
|------|------|------|
| 1 | 多租户 SaaS 基础架构 | 租户隔离、JWT 多域认证（平台/商户/消费者/经销商）、RBAC 权限 |
| 2 | 平台运营管理 | 商户入驻审核、主数据 SKU 管理、配额下发、要货审批、配送发货、资金/结算/提现 |
| 3 | 分店经营管理 | 门店销售、自提核销、分店资金、补货请求、库存管理（仓库/采购/调拨/盘点） |
| 4 | 渠道分销管理 | 拓店邀请、分店业绩看板、佣金计算与提现申请 |
| 5 | 消费者电商 | 店铺选择、商品浏览、购物车、自提/配送结账、订单跟踪、核销码验证 |
| 6 | B2B 电商与佣金 | 订单履约驱动的佣金计提（FULFILLED 触发）、结算批次导出、提现审批 |
| 7 | AI Agent 智能诊断 | 自然语言查询、LLM 多轮 Tool 调用、跨域数据综合、结构化诊断报告 |
| 8 | 国际化与本地化 | 中/英双语界面、CNY 币种、符合国内财务口径 |

## 4    风险评估和规避

### 技术风险

| 风险描述 | 发生概率 | 影响程度 | 规避措施 |
|----------|----------|----------|----------|
| 多租户数据隔离缺陷导致数据泄露 | 低 | 极高 | TenantInterceptor 全局拦截 + Prisma 查询强制 `tenantId` 过滤 + 安全审计日志；每次 CRUD 操作须经 Code Review |
| JWT 多域认证密钥泄露 | 低 | 极高 | 四套独立 JWT 密钥分离存储；环境变量管理；定期轮换；禁止硬编码 |
| LLM API 不可用导致 AI 诊断中断 | 中 | 中 | 双 Provider 切换（OpenAI/Anthropic）；超时降级返回友好错误提示；诊断功能为非关键路径，不影响核心业务 |
| LLM 输出幻觉导致错误诊断 | 中 | 中 | 所有结论必须来自 Tool 返回的真实数据；System Prompt 约束禁止臆测；卡片状态由 Tool 数据驱动而非 LLM 自由发挥 |
| 高并发下数据库性能瓶颈 | 中 | 高 | Prisma 查询优化（索引、连接池）；Redis 缓存热数据；BullMQ 异步处理佣金计算和邮件发送 |
| Stripe 支付回调丢失或重复 | 低 | 高 | Stripe webhook 签名验证 + 幂等处理；PaymentIntent ID 唯一约束；mock 模式下完整覆盖异常路径测试 |

### 管理风险

| 风险描述 | 发生概率 | 影响程度 | 规避措施 |
|----------|----------|----------|----------|
| 需求范围蔓延导致进度失控 | 高 | 高 | Phase gate 机制：每阶段开始前锁定 PRD；变更须经评审委员会审批；PRD v2 明确标定 Deprecated 项 |
| 关键人员离职导致知识断层 | 中 | 高 | Handoff 文档制度（每阶段结束输出 Handoff block）；代码文档化；核心模块至少两人知晓 |
| 前后端接口契约不一致 | 中 | 中 | `@meridian/shared` 包统一类型定义；API 先定义 DTO 再实现；E2E 测试覆盖关键接口 |
| 多门户并行开发导致集成冲突 | 中 | 中 | monorepo 统一依赖管理；Turborepo 构建编排；feature branch 基于 develop 分支，PR review 合并 |

### 其它风险

| 风险描述 | 规避措施 |
|----------|----------|
| 代码版本管理和备份 | Git 托管远程仓库（GitHub）；main/develop/feature 三分支模型；每次 Push 触发 CI 构建验证 |
| 第三方服务依赖（Stripe、LLM API） | Stripe mock 模式支持离线开发；LLM Provider 抽象接口支持切换；关键路径不依赖外部服务 |
| 数据库迁移失败 | Prisma migrate 前备份数据库；所有迁移脚本纳入版本控制；CI 流水线包含 migrate 验证步骤 |
| 生产环境部署故障 | Docker Compose 全栈容器化；环境变量通过 `.env` 管理；回滚方案：Git tag + 上一版本镜像 |
